\section{Introduction}
\logan{If we have time, we could run RPNI and EDSM separately also. But for now we just have results from our single gridsearch winner (RPNI-like)}
This paper compares the results of a state merging algorithm and four neural network architectures on an extension of \textsc{MLRegTest}, a benchmark for the  learning of regular languages \citep{mlregtest}.
The training data of \textsc{MLRegTest} contains only strings of at least length 20, but \citet{adil23} demonstrated that augmenting this with shorter strings led to significant improvement in the performance of the state merging algorithms. 
Following \citeauthor{adil23}, we compare performance of both state merging and neural models when trained on the original \textsc{MLRegTest} data, the augmented \citeauthor{adil23} data, and training data containing \textit{only} strings of length 19 or less.

\section{Learning Systems} \label{sec:bg}

\subsection{State-Merging Systems}
Following \citet{adil23}, we make use of the state-merging algorithms provided by \textsc{FlexFringe} \citep{flexfringe-short, flexfringe}.\footnote{We use the same version of \textsc{FlexFringe} used by \citeauthor{adil23}: commit \texttt{4d1449c} of the software available 
\href{https://github.com/tudelft-cda-lab/FlexFringe/commit/4d1449c4d0cfb3fc5f9a954d5c3a24a11a593a5c\#diff-67290ef9e84d355c83cbd9a0bda3be39e2e14836990458cfcc070506a7e448c2}{here}.
}
\textsc{FlexFringe} provides implementations of the EDSM \citep{edsm} and RPNI \citep{rpni}state-merging algorithms:\footnote{We exclude ALERGIA from consideration because of the infeasibly high compute demands and comparatively low performance noted by \citeauthor{adil23}} both take as input a set of strings labeled by their membership in the target langauge, and construct a prefix tree from these strings. 
A search is then conducted for pairs of states to merge: RPNI does so in a breadth-first fashion, selecting pairs closest to the initial state. 
EDSM instead computes a score for all possible pairs and attempts to merge the one with the highest score.\footnote{Notably, the implementation of RPNI in \textsc{FlexFringe} differs slightly from that in \citet{rpni}: while \citeauthor{rpni} merged states in length-lexicographic order when ties arise, \textsc{FlexFringe} instead calculates a score, akin to EDSM. } 

\textsc{FlexFringe} also provides several other parameters which impact learning behavior. To find the best model, we conducted a limited gridsearch over the following subset\footnote{We held several other parameters at their default state because modifying them led to errors in the \textsc{FlexFringe} executable. These are: \textsc{ReverseTraces}, \textsc{DepthCheck}, \textsc{SymbolCheck}, \textsc{SinksOn}, \textsc{SinkCount}, and \textsc{MergeScore}.}:
\begin{itemize}
\item \textsc{PerformFirst:}  whether the algorithm should perform EDSM or RPNI 
\item \textsc{Extend}: extend (color red) blue states that cannot be merged with any red
\item \textsc{ShallowFirst}: consider coloring blue states closest to the root first
\item \textsc{SearchStrategy}: searchdeep, searchlocal, searchglobal, searchpartial, none \todo{They have absolutely no documentation of what these parameters do, should we  just guess? }
\end{itemize} 

Grid searching was carried out on the small partition of the \textsc{PlusShort} data using overall accuracy on the development set (see \S \ref{sec:eval}). 
The best performing model, used in the remainder of the paper, was \textsc{PerformFirst = 0} (i.e., RPNI), \textsc{Extend = 1}, \textsc{ShallowFirst = 0}, and \textsc{SearchStrategy = SearchDeep}. 


\subsection{Neural Systems}
Following \citet{mlregtest}, we test four neural architectures, all consisting of a trainable embedding layer followed by a unidirectional recurrent module (either a \textbf{\textsc{Simple}} RNN, a \textbf{GRU}, or an \textbf{LSTM}) or two consecutive \textbf{\textsc{Transformer}} blocks, dense feed-forward layers, dropout, layer normalization, and softmax activation. 
All neural networks are implemented with TensorFlow and Keras \citep{tensorflow, keras} and use the same hyperparameters as \citet{mlregtest}.\footnote{Implementations of the neural networks are available at: \href{https://github.com/heinz-jeffrey/subregular-learning/}{https://github.com/heinz-jeffrey/subregular-learning/}}

We evaluate our learning models with an extension of \textsc{MLRegTest} \citep{mlregtest}, which contains training, development, and test data with and equal number of positive and negative examples of strings from 1,800 languages.
We follow \citet{adil23} in excluding those languages with alphabet sizes of 64 due to unicode errors, thus considering 1,140  languages. 

The original \textsc{MLRegTest} training data contains strings with length 20-29.
\citeauthor{adil23} conducted a follow-up experiment in which this was augemented with roughly 1,000 short training strings (length 1-19). 
The authors found that this change significantly improved the performance of \textsc{FlexFringe} models.
In the current work, we build on \citeauthor{adil23} by considering three training setups:
\paragraph{\textsc{OnlyShort}:} models are trained on only the short strings from \citet{adil23}
\paragraph{\textsc{PlusShort}:} models are trained on  \textsc{MLRegTest}  augmented with short strings, replicating \citet{adil23}
\paragraph{\textsc{OnlyLong}:} models are trained on the original \textsc{MLRegTest} data

\textsc{MLRegTest} is designed to investigate a number of potential factors which may contribute to model performance, summarized with our additions in Table \ref{tab:experimental-setup}. 
It additionally contains four testing sets per language, based on the length of the strings (\textsc{Short} = 20-29, \textsc{Long} = 31-50) and the method of generation (\textsc{Random}, sampled randomly without replacement or \textsc{Adversarial}, with paired positive and negative examples with an edit distance of 1). 
We report results separately on each test set.

Table \ref{tab:overall-scores} gives the F1 score of each model, averaged across languages and test types; breakdowns by test type are given in Tables \ref{tab:OS-by-test}-\ref{tab:OL-by-test} in the Appendix.
Though the GRU consistently outperforms the other models, we note that it takes much greater of a hit in performance between \textsc{PlusShort} and \textsc{OnlyShort} than \textsc{FlexFringe}, which outperforms all other neural architectures on \textsc{OnlyShort}. 
Figure \ref{fig:f1-diff-ps-os} illustrates the difference in average F1 between the \textsc{PlusShort} small train size and \textsc{OnlyShort} by model and test set: \textsc{FlexFringe} has the smallest difference in performance on the random test sets, and is comparable to the \textsc{Simple} RNN on the adversarial ones; the GRU shows the largest difference in performance on these test sets. 

Similarly, we note that \textsc{FlexFringe} sees the largest jump in performance from \textsc{OnlyLong} to \textsc{PlusShort}; this is illustrated in Figure \ref{fig:f1-diff-ps-ol}. 
Taken together, these results suggest that \textsc{FlexFringe} benefits far more from the inclusion of short strings, while the neural models --- particularly the GRU --- rely heavily on long strings to achieve their performance. 
Further breakdowns of performance by language class are given in Figures \ref{fig:os-by-class}-\ref{fig:ol-by-class} in the Appendix.
